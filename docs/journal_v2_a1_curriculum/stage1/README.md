## Stage-1 environment (configuration/wrapper only; frozen in `protocol.json`, SHA-256 recorded)
- **Asset:** canonical C0 V2 config with `v_s = 0`, so the asset never moves after reset (canonical reset puts it at the origin on the ground). Together with the canonical `defender_standby_until_detection = False` these are the only two config differences from canonical C0 V2 (checked by test).
- **Defender:** established parked semantics (never acts, state kept, not synchronised onto the asset) at a **ground-level arena corner (−48, −48, 0)**. The environment clamps any defender into the 50 m volume, so "outside the arena" is impossible without touching the simulator; the corner position was chosen from data: A0 never closer than 9.0 m (600 episodes), defender inside the 25 m information gate in ~7.5% of episodes (stationary, non-threatening). In *stochastic training* the parked defender still intercepted 1.4–3.2% of episodes (random-walk-like exploration), never A0.
- **Clutter:** C0. **Observation** `a1_v2_obs_v1` (37-D), **reward** `a1_v2_reward_v2` (no Stage-1 reward), **PPO** unchanged (MlpPolicy [64,64] tanh, lr 3e-4, γ 0.99, λ 0.95, 2048 steps × 16 envs, batch 64, 10 epochs, clip 0.2, ent 0.01, vf 0.5, grad-norm 0.5; seeds 201/202/203; no tuning).
- **Action** `a1_cur1_action_v1`: `Box(-1,1,(3,))` → unit desired direction handed to the canonical constrained dynamics. A near-zero or non-finite action **holds the current velocity direction** (+x at rest); it is deliberately *not* the environment's own fallback, which would silently return the A0 pursuit command (tested).
- **Training geometry:** canonical reset (attacker uniform on the 50 m square perimeter, altitude U(10, 30) m, 3-D range ≈ 50–90 m) plus a pre-registered random initial heading (line of sight rotated by α ~ U(0°, 90°), uniform azimuth; vertical rate clipped as in the canonical reset), so "keep flying straight" is not enough. Scenario streams are keyed to (seed, worker, rollout).

## Protocol
One rollout = 32,768 steps, ≤ 8 rollouts/seed. After every rollout: atomic commit (manifest renamed last) → mirror to OneDrive → held-out validation (rollout odd: set A = 146000–146099, even: set B = 146100–146199; deterministic policy) → mastery gate (capture ≥ 98%, 0 collisions, exhaustion ≤ 1%, timeout ≤ 1%, median path-excess ≤ 1.20×, >2× ≤ 2%, >5× = 0, pathology ≤ 2% with no orbit, no non-finite values) on **two consecutive** rollouts. Scratch `C:\Users\Public\journal_v2_a1_curriculum\stage1\` (local, non-OneDrive); models in `results/.../a1_curriculum/stage1/` (distinct namespace, gitignored).
**Real-SB3 resume validation** (`resume_validation.json`): tiny real PPO on `SubprocVecEnv`, interrupted run (injected abrupt death between model write and manifest, partial files discarded, dead-PID lock, process-level reload) vs uninterrupted run: policy+optimizer state hashes and episode logs **bit-identical for all 3 rollouts**. This required keying scenario streams and a forced env reset to the rollout index (so a rollout is a pure function of state + rollout index).

## What the policies learned (post-hoc diagnostics, `diagnostics.json`; not part of the mastery protocol)
- Mean cosine between the deterministic action direction and the line of sight to the asset: **0.07 / −0.005 / 0.014** — no goal-directed steering. Learned action std ≈ 1.02 (initial 1.0): exploration noise did not shrink.
- Training episodes (stochastic policy): 96–98% end by endurance exhaustion after ~73 steps (sampled directions ≈ uniform random), 0.5–4% captures, 1.4–3.2% parked-defender interceptions; mean training return −18.0 (seeds 202/203 flat) and −18.0 → −17.0 (seed 201, improving only in the last three rollouts).
- Seed 201's captures are only mildly heading-dependent (mean initial heading offset of captured scenarios 46° vs 56° for failures; 40 diagnostic episodes), so they are not simply "already pointing at the asset" cases.
**Interpretation (hypothesis, not tested here):** with an unbounded Gaussian over a normalized direction (σ ≈ 1 against a unit-range action), the sampled direction is nearly random, so the reward gradient toward "turn to the asset" is swamped; eight PPO updates are not enough. Seed 201's late rise suggests learning had just begun, so this result does **not** show that PPO cannot learn Stage 1 — it shows that **this untuned configuration does not within the pre-registered 262,144-step budget**.
