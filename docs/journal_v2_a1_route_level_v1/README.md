## Architecture (frozen before the sweep: `route_interface_specification.json`)
A1 would select `Discrete(4)`: DIRECT / EVADE_LEFT / EVADE_RIGHT / EVADE_ABOVE. `m = (p_s − p_a)/‖·‖`, `s = clip((p_d − p_a)·m, 0, ‖p_s − p_a‖)`, `q = p_a + s m`, `l = normalize(ẑ × m_h)`; subgoals `q_L = q + R l`, `q_R = q − R l`, `q_U = q + R ẑ` (ceiling-capped); R ∈ {5, 7.5, 10} m, T_replan ∈ {1, 2} s (2 / 4 steps) → 6 configurations. The existing visibility-graph/A* planner (`build_and_search_route`) plans attacker → subgoal → asset from the **perceived static set only**; a persistent waypoint follower hands the direction to the frozen common obstacle layer (final authority) and the frozen dynamics. DIRECT returns the zero override, i.e. canonical A0. Rules: validate-before-commit (`defender_not_ahead`, `degenerate_geometry`, `ceiling`, `no_path`, `non_finite`, `planner_collision` → DIRECT), defender gate (no information → everything collapses to DIRECT), route persistence with cadence / blocked-route / asset-moved / info-lost triggers, completion → DIRECT, and a **post-completion DIRECT hold of one replan interval** (added after a 4-scenario smoke test and before any sweep, because a route that re-arms on the step it completes loops; recorded in the specification; a unit test then caught that the first implementation re-armed on the completion step itself). ## Planner and perception audit (`route_planner_audit.json`)
The existing planner is perception-constrained by construction (input: `PerceivedObstacleSet`, static AABBs only; dynamic obstacles are never read), supports moving targets and replans, and is **not** used by canonical A0 (V2 disables route planning). It needs no privileged information beyond the canonical `map_local` contract: in C1–C3 every static obstacle is map-known and dynamic obstacles are only locally sensed. G5 evidence: the controller module contains none of the forbidden world-state references (checked by test), 0 planner calls without defender information, 0 obstacle ids outside the perceived set (≈ 160,000 planner calls), DIRECT ≡ A0 bit-for-bit in every cell checked; because all static obstacles are map-known in the canonical contract, "unperceived static obstacles at planning time" is 0 by construction, so a counterfactual test under `local` awareness (undiscovered obstacles exist) shows the planner uses only the perceived subset.

## Sweep protocol and coverage — **read this**
Pre-registered: 6 configurations × 4 clutter levels × 5 defenders × 100 seeds × 8 scripted policies (DIRECT, LEFT, RIGHT, ABOVE, alternating, random, max-separation, adversarial switching). **What was actually run (staged, 48,000 episodes): C0 × {greedy, Kalman-greedy, PN, lead} and C1–C3 × {greedy, PN}, all 6 configurations; RMPC and the remaining C1–C3 defenders were NOT run.** Reason: a first launch ordered RMPC cells first and took > 75 min without finishing a cell (RMPC ≈ 1 s per step, and evasion episodes last up to 50 steps instead of ≈ 10); the full grid was estimated at > 12 h. G1 and G2 are monotone against a DIRECT baseline with 0 collisions and 0 exhaustions in every cell (more episodes can only add failures), so failing them on the evaluated subset already fails every configuration; G3/G4 are pooled statistics and were evaluated on the same subset. The discarded RMPC-first launch produced no cells. The specification hash is unchanged by this staging.

At C0 alone (400 episodes) LEFT/RIGHT/ABOVE reach 210–349 exhaustions; every exhausted episode contains a fly-by and ≈ 90–95% were DIRECT interceptions that the route survived but could not convert.
- **G3 passes (authority large and positive)**: up to 351 interception→capture conversions vs 68 reversals (ABOVE, R 5, T 2; net +283 captures on a DIRECT base of 97 / 1,000); MAX_SEP (and ALT_LR at R 5, T 1) are the only policies with negative net captures.
- **G4 fails 6/6**: >5× path-excess 1,031–1,686 cases (88–91% endurance exhaustions, 7–8% long chases that still end in capture, the rest collisions/interceptions) vs 0 for DIRECT (max 1.06×); tactical max up to 17.5×.
- **G5 passes** (above). **G6 fails 6/6 under the pre-registered metric** (6 planner calls in a 4-step window vs the bound of 3, because validation rejections of an every-step request count as calls); no non-finite values, deterministic replay passes, longest route run 16–22 steps (≤ 40), mean 2–2.1 waypoints, 30–37% of attempts rejected (mostly `defender_not_ahead`).
- **Mechanisms**: 237 of 240 sampled gained collisions occur while the frozen layer already owns steering, 179 of them more than 3 steps after the route ended — long post-evasion exposure rather than collisions on the route itself.
- **Selection**: no configuration passes → `selected_configuration.json` deliberately absent; manual diagnostic recordings and the PPO training-runner dry run were not produced (they apply only to a passing configuration).

## Interpretation and limits
Route-level selection moves the problem above the heading layer: collisions no longer happen on the maneuver and the evasion authority is far larger than at heading level. But the scripted always-on policies make the attacker fly past the asset after the evasion subgoal (the subgoal sits near the mission line close to the defender, which defends the asset), and the survived episode lasts ≈ 5× longer, so the pre-registered mission and safety gates fail. This does not show that a learned or gated selector could not use the interface well (its capture gains are real), only that the interface as specified, with re-arming allowed, is not safe by construction. Not tested: a mission-aware subgoal that commits to the asset after the pass, a limit on prolonged episodes, RMPC and the remaining C1–C3 defenders (see coverage).
